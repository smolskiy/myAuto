# Волна 1 · domain-data — расчёты, каталог, VIN, база и хуки: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Вся предметная логика «Мой авто» как чистые функции с тестами (`src/domain/**`) и живые React-хуки
(`src/db/hooks.ts`), которые склеивают базу (репозитории волны 0) с расчётами.

**Architecture:** `domain/` — чистый TypeScript без React/Dexie, каждая функция детерминирована (сегодняшняя дата
передаётся параметром `today`). Репозитории, слияние, даты и id уже сделаны в волне 0; здесь — расчёты и хуки
на `useLiveQuery`, которые склеивают данные базы с расчётами `domain/calc`. Экраны (волна 2) работают только через хуки и репозитории.

**Tech Stack:** TypeScript 6, Vitest 5, fake-indexeddb, Dexie 4.4, dexie-react-hooks, @testing-library/react.

**Spec:** `docs/superpowers/specs/2026-09-25-myauto-design.md` (разделы 4, 5, 7.2, 12)

**Зона агента:** `src/domain/**` и `src/db/hooks.ts`. Файлы волны 0 (`domain/types.ts`, `snapshot.ts`, `dates.ts`, `ids.ts`,
`merge.ts`, весь `src/db/**` кроме `hooks.ts`) не менять — нужные правки описать в отчёте.
Не трогать `src/ui`, `src/sync`, `src/features`, `src/app`. Новых npm-зависимостей не добавлять.

## Global Constraints

- Деньги — целые копейки (`Kopecks`); при делении — `Math.round` до копейки.
- Даты — `ISODate` `'YYYY-MM-DD'`; никаких `new Date()` внутри `domain/` без параметра `today`/`now`.
- Строки с `deleted: true` игнорируются всеми расчётами и списками (кроме `readSnapshot`).
- Числа для людей: разделитель тысяч и пробел перед единицей — U+00A0 (неразрывный пробел), десятичный разделитель — запятая.
- Каждый публичный модуль — со своим `*.test.ts` рядом.
- Перед отчётом: `npm run typecheck && npm run lint && npm test` зелёные.

## Review Focus

1. **Ввод пробега задним числом** — новая запись в середине истории; хронология проверяется относительно соседей
   по дате, а не относительно «текущего пробега». Тест — Task 4.
2. **Правка существующей записи** — проверка хронологии исключает саму редактируемую запись. Тест — Task 4.
3. **Несколько заправок подряд без полного бака и «пропустил заправку»** — расход не искажается. Тест — Task 5.
4. **Полис продлён заранее** — новый полис с более поздней датой вытесняет истекающий, в «Скоро» остаётся один. Тест — Task 6.
5. **Итог ТО введён вручную и меньше суммы строк (скидка)** — статистика сходится с итогом записи. Тест — Task 7.

```ts
export function fuelIntervals(records: CarRecord[]): FuelInterval[] {
  const hasOdo = (f: FuelRecord) => typeof f.odometer === 'number'
  const fills = records
    .filter((r): r is FuelRecord => r.kind === 'fuel' && !r.deleted)
    .sort((a, b) => a.date.localeCompare(b.date) || (a.odometer ?? 0) - (b.odometer ?? 0))
  const out: FuelInterval[] = []
  let start: FuelRecord | null = null
  let liters = 0
  for (const f of fills) {
    if (f.missedBefore) { start = f.fullTank && hasOdo(f) ? f : null; liters = 0; continue }
    if (!start) { if (f.fullTank && hasOdo(f)) { start = f; liters = 0 } continue }
    liters += f.liters
    if (f.fullTank) {
      if (!hasOdo(f)) { start = null; liters = 0; continue } // полный бак без пробега — интервал не замкнуть
      const km = f.odometer! - start.odometer!
      if (km > 0) out.push({ fromId: start.id, toId: f.id, fromDate: start.date, toDate: f.date, km, liters, lPer100km: (liters / km) * 100 })
      start = f; liters = 0
    }
  }
  return out
}
```
